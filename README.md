# نظام إدارة المهام — قسم المشتريات

موقع ويب مبني من ملف `Task_Management.xlsx`، بنفس أعمدته وقوائمه ومنطق حساب تاريخ الاستحقاق.

## الملفات

| الملف | الوظيفة |
|---|---|
| `index.html` | الموقع كامل — الواجهة والمنطق وقاعدة البيانات المحلية. يعمل بمجرد فتحه. |
| `firebase-adapter.js` | اختياري. عند تفعيله تصبح البيانات مشتركة بين الجميع لحظياً بدل كونها محلية لكل جهاز. |

لا يحتاج المشروع إلى تثبيت أي شيء ولا خطوة بناء (build).

---

## 1. التشغيل الآن

افتح `index.html` بأي متصفح.

- اختر اسمك من القائمة، وكلمة المرور الافتراضية للجميع: **`1234`**
- غيّرها من تبويب **الإعدادات** بعد أول دخول.

الصلاحيات:

| الدور | من | الصلاحية |
|---|---|---|
| مسؤول النظام | عبدالإله | كل شيء + إضافة وحذف المستخدمين |
| مدير | م. مروان، م. بو، م. يو | إسناد المهام، تعديل وحذف أي مهمة |
| موظف | محسن، أكرم، إسماعيل، منصور | يرى كل المهام، ويعدّل حالة وملاحظات وتاريخ إنجاز مهامه هو |

### ما ينقله الموقع من ملف الإكسل

- الأعمدة الاثنا عشر بنفس ترتيبها وأسمائها الإنجليزية (يظهر تصدير CSV مطابقاً للورقة).
- القوائم المنسدلة: النوع، الأولوية، الحالة، مُسندة من، مُسندة إلى.
- حساب **تاريخ الاستحقاق** تلقائياً من الأولوية: P1 و P2 نفس اليوم، P3 بعد 3 أيام، P4 بعد 7 أيام، و P5 يدوي.
- لوحة `Dashboard`: عدد المهام لكل شخص موزّعة على الحالات، وما ينفّذه كل شخص الآن.
- ورقة `INDEX` كاملة في تبويب **المرجع**.

### إضافات ليست في الإكسل

- كشف المهام المتأخرة تلقائياً بمقارنة تاريخ الاستحقاق باليوم.
- بحث وتصفية حسب الموظف والحالة والأولوية والنوع.
- تصدير CSV يفتح مباشرة في إكسل، ونسخة احتياطية JSON للاستعادة.
- واجهة عربية/إنجليزية بزر واحد، وتعمل على الجوال.
- طباعة الجدول المُصفّى (زر «طباعة»).

## 2. الرفع على GitHub Pages

هذه أسرع طريقة لجعل الموقع على رابط يفتحه الجميع.

1. أنشئ مستودعاً جديداً على GitHub باسم `task-management` واجعله **Private** إن كانت البيانات داخلية.
2. ارفع `index.html` و `firebase-adapter.js` و `README.md` إلى المستودع (زر *Add file* ← *Upload files*).
3. من **Settings** ← **Pages**: في *Source* اختر `Deploy from a branch`، والفرع `main` والمجلد `/ (root)`، ثم *Save*.
4. بعد دقيقة تقريباً يصبح الرابط:
   `https://<اسم-حسابك>.github.io/task-management/`

> ملاحظة: مستودعات GitHub Pages المجانية تنشر الموقع **علناً** حتى لو كان المستودع خاصاً في الخطط المجانية. إن أردت رابطاً غير علني استخدم Firebase Hosting في الخطوة 3.

---

## 3. الرفع على Firebase Hosting

```bash
npm install -g firebase-tools
firebase login
cd <مجلد-المشروع>
firebase init hosting      # اختر Use an existing project، واجعل public directory = .
firebase deploy
```

عند سؤال `Configure as a single-page app?` أجب **No**، وعند `Overwrite index.html?` أجب **No**.

## 4. تفعيل قاعدة بيانات مشتركة (Firestore)

بدون هذه الخطوة، بيانات كل شخص محفوظة في متصفحه فقط ولا يراها غيره. مع هذه الخطوة يرى الجميع نفس المهام، وأي تعديل يظهر لدى الباقين خلال ثانية.

**أ. أنشئ المشروع**

1. [console.firebase.google.com](https://console.firebase.google.com) ← *Add project*.
2. **Build ← Firestore Database ← Create database** ← اختر `Start in production mode` وأقرب منطقة (`eur3` أو `asia-south1`).
3. **Build ← Authentication ← Get started ← Sign-in method ← Anonymous ← Enable**.
4. **Project settings ← Your apps ← Web (`</>`)** ← سجّل التطبيق ← انسخ كائن `firebaseConfig`.

**ب. اربط الموقع**

1. الصق القيم في `FIREBASE_CONFIG` أعلى ملف `firebase-adapter.js`.
2. في `index.html` احذف علامات التعليق حول هذا السطر قرب نهاية الملف:

```html
<script type="module" src="firebase-adapter.js"></script>
```

**ج. قواعد الأمان**

في **Firestore Database ← Rules** ضع:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /boards/{board}/{collection}/{docId} {
      allow read, write: if request.auth != null;
    }
  }
}
```

**د. تحقق**

افتح الموقع، ثم افتح Console في المتصفح (F12). يجب أن تظهر رسالة `connected to Firebase`. إن ظهر بدلها خطأ، فالموقع يعود تلقائياً للتخزين المحلي ولن تفقد شيئاً.

قبل التفعيل: صدّر نسخة JSON من **الإعدادات ← تنزيل نسخة**، وبعد التفعيل استعدها من نفس المكان لترفع مهامك الحالية إلى Firestore.

## 5. ملاحظة مهمة عن الأمان

شاشة الدخول الحالية تفصل المستخدمين عن بعضهم وتمنع الخلط في المهام، لكنها **ليست حماية أمنية**: كلمات المرور محفوظة مع البيانات، ومن يفتح أدوات المطوّر في المتصفح يستطيع تجاوزها.

هذا مقبول لأداة داخلية على شبكة الشركة. أما إن كان الموقع سيوضع على رابط عام يحمل بيانات موردين وعقود، فالخطوة الصحيحة هي **Firebase Authentication** بالبريد وكلمة المرور: حساب لكل شخص من لوحة Firebase، واستبدال شاشة الدخول الحالية باستدعاء `signInWithEmailAndPassword`، ثم تشديد القواعد أعلاه لتقييد الكتابة على المستخدم صاحب المهمة. عندها تصبح كلمات المرور محفوظة عند Google ولا تمر عبر ملفات الموقع إطلاقاً.

كذلك: قواعد الأمان في الخطوة (ج) تسمح لأي زائر يسجّل دخولاً مجهولاً بالقراءة والكتابة. هي كافية لمنع الوصول العشوائي من خارج الموقع، لكنها ليست بديلاً عن حسابات حقيقية.

## 6. تعديلات شائعة

| ماذا تريد | أين | ملاحظات |
|---|---|---|
| إضافة أو حذف موظف | تبويب **الإعدادات ← المستخدمون** | لا حاجة لتعديل الكود |
| تغيير أيام الاستحقاق لكل أولوية | `index.html` ← `TARGET_DAYS` | الأرقام بالأيام، و `null` تعني يدوي |
| إضافة نوع مهمة أو حالة جديدة | `index.html` ← `TYPES` أو `STATUSES` | أضف ترجمتها في `LBL` و `REF_MEANING` |
| تغيير الألوان | `index.html` ← كتلة `:root` في أعلى ملف الأنماط | |
| اسم المشروع في الترويسة | `index.html` ← المفتاح `project` داخل `T.ar` و `T.en` | |
